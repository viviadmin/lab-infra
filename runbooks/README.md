# Runbooks

One runbook per service. Written **after** the service is running, refined as
I operate it. Each runbook answers, in order:

1. What is this service for?
2. On which host does it run?
3. Common operations (start/stop/restart/reload/logs)
4. Top 3 troubleshooting scenarios, with commands
5. Backup & restore
6. Dependencies

Runbooks are **published evidence** of operational thinking. They differ from
`docs/decisions.md` (architecture) and `troubleshooting/` (dated incidents).
